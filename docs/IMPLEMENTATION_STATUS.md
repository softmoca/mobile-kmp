## 계약상 제한

- 서버에 refresh API, 회원 삭제 API, 임의 질문 생성 API가 없다. 없는 API를 추측해 구현하지 않았다.
- 사용자 체크리스트는 시스템 항목을 조합한다. 과거 임의 질문이 포함된 템플릿은 표시하되 지원하지 않는 재저장을 막는다.
- 사진은 한 번에 한 장씩 추가한다. 서버 허용 5MiB를 초과하면 안내한다.
- 실제 API 검증은 새 격리 회원을 사용했다. 테스트 매물/사진/체크리스트는 정리했으며 계정 삭제 API가 없어 API smoke 회원 2개는 남는다.
- iOS UI smoke 회원도 무작위로 생성했다. 실패 재시도 회원을 포함해 삭제 API가 없어 남으며, 기존 사용자의 회원·데이터는 변경하지 않았다.
- mock은 테스트 코드에만 존재한다. 일반 앱에 가짜 결과를 실제 데이터처럼 보여주는 경로가 없다.

## 남은 검증과 우선순위

1. **P1 — 실기기 검증:** Android/iPhone 위치 권한 거부·재허용, 사진 선택(HEIC 포함), PDF 저장·외부 앱 공유, 앱 재시작 후 보안 저장소 복구를 확인한다. 물리 기기와 개인 Apple 서명은 아직 사용하지 않았다.
2. **P1 — 배포 준비:** 자신의 앱 ID·Android Release 서명·Apple Team/서명, 개인정보 안내와 스토어 요구사항을 준비한다. 운영 API에 테스트 데이터를 쓰거나 앱을 배포하지 않았다.
3. **P2 — 지도 서비스 운영:** 기본 OSM 표준 타일은 best effort이며 대규모 서비스 SLA가 없다. 사용량에 맞는 타일 제공자 계약/정책을 검토한다. 유료 리소스는 만들지 않았다.
4. **P2 — 편집 편의:** 미저장 입력을 두고 뒤로 나갈 때 확인 창, 다중 사진 선택, 개별 기기 접근성·큰 글꼴 QA는 후속 개선 범위다.

Xcode 27은 선택한 Kotlin 버전의 공식 호환표보다 새롭다. 이 환경에서의 실제 결과는 BUILD_REPORT에 별도로 명시하며 모든 Xcode 버전에서 검증됐다고 주장하지 않는다.
