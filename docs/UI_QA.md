# 모바일 UI 검증 기준

2026-10-27 기준. 상위 팀 저장소의 최신 React `features/auth`, 매물 목록·상세·체크리스트·지도·마이 흐름과 Controller를 읽기 전용으로 참고했다. 코드를 구현하거나 검토한 사실과 실제 기기에서 확인한 결과를 구분한다. 실행 증거는 [BUILD_REPORT](BUILD_REPORT.md), iPhone 수동 점검은 [IPHONE_QA](IPHONE_QA.md)를 따른다.

## UI 변경에서 지키는 조건

- 처음 빈 목록, 검색 결과 없음, 통신 실패를 각각 안내한다. 서버의 실제 빈 목록에 예시 매물을 넣지 않는다.
- 완료는 `totalCount > 0 && completedCount >= totalCount`다. 체크 항목 0개를 완료로 표시하지 않는다.
- 매물명·주소는 목록에서 제한된 줄 수로 표시하고 상세에서 확인한다. 사진이 없으면 빈 카드 대신 사진 없음 상태를 보인다.
- 생성 경로를 상세 ID 경로와 분리해 iOS Navigation 2.9.1에서 등록 버튼이 빈 화면으로 연결되던 문제를 수정했다.
- Scaffold가 적용한 시스템/키보드 여백은 NavHost에서 소비한다. 키보드가 올라왔을 때 하위 폼이 같은 여백을 다시 적용해 이름 입력칸만 남던 문제를 수정했다.
- 갱신 중 이전 화면을 유지하고 실패하면 오류와 재시도를 보인다. 체크 상태를 누를 때 화면 전체를 로딩 화면으로 교체하지 않는다.
- 주소 검색의 오래된 응답, 변경된 위치/반경/카테고리의 시설 응답이 현재 선택을 덮어쓰지 않는다.
- 사진 한 장 선택, 명시적 주변 조회, 원 단위 금액 입력은 모바일의 현재 동작이다. 시스템 picker 취소를 업로드 성공으로 표시하지 않는다.
- 사용 중인 회원의 기록을 로그아웃이나 앱 재설치로 되찾을 수 있다고 안내하지 않는다. 쿠키 만료·저장소 삭제·Bundle ID 변경은 기록 연결에 영향을 준다.

## 자동 검사와 한계

`ScreenStateTest`와 `RecordPresentation` 테스트는 코루틴 상태·필터 로직을 검사한다. 새로고침 시 화면 유지, 이전 조회가 저장된 메모를 덮어쓰지 않는 조건, 0개 체크의 완료 오분류 방지를 포함한다. 실제 큰 글꼴이나 화면 겹침을 자동 판정한 것은 아니다.

`iosAppDevSmoke`는 새 QA Simulator에서 실제 개발 API를 사용한다. 최초 익명 진입, 마이 회원 번호, 앱 프로세스 재시작 후 같은 회원, MapKit, 긴 QA 매물명/주소·사진 없음, 메모 저장과 재실행 조회, 테스트 매물 삭제를 검사하도록 작성했다. 기본 `iosApp` scheme은 앱 실행 전에 skip하여 무단 익명 회원 생성을 막는다. 최신 실행 결과와 실패 수정은 BUILD_REPORT에만 확정해서 기록한다.

실제 dev API smoke는 별도 익명 회원에서 매물·메모·사진·체크리스트·PDF·시설을 검증한다. API 성공은 사진 선택기·GPS·파일 앱·외부 공유 성공을 뜻하지 않는다. 정상 실행은 매물·체크리스트 정리와 빈 목록까지 확인하며 익명 회원은 삭제 endpoint가 없어 남는다.

## iPhone에서 이어서 확인할 항목

1. 같은 Bundle Identifier로 Debug 재설치 후 회원 번호와 기록 유지, 종료·오프라인·복구.
2. 작은 화면·큰 글자·한글 키보드에서 저장 버튼 접근, 긴 질문/주소 줄바꿈, 다수 매물 스크롤과 필터.
3. 체크 상태 연속 변경 후 스크롤과 완료 집계, 사진 작업 뒤 작성 중 메모 유지.
4. HEIC/JPEG 선택·취소·용량 초과·대표 변경, 실제 위치 권한 거부/재허용·대략 위치.
5. 2~5개 비교, PDF 한글·사진·순서 시각 검수, Files 저장·재열기·공유 시트 취소.
6. 테스트한 `KMP QA` 항목만 정리하고 평소 익명 기록을 유지한다.

미저장 폼 이탈 확인과 다중 사진 업로드는 아직 없다. 폼을 나가기 전에 저장해야 한다. App Store/TestFlight·Android 실기기·행동 분석은 이번 검증 범위에서 제외한다.
